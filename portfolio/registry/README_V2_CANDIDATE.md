# Federated Portfolio Registry 2.0 candidate

This additive candidate reconciles the legacy 28-project planning registry with the August 20 portfolio integration audit and bounded GitHub, Vercel, and Sites readback.

It does not replace `projects.json`. The pointer pins that legacy file's exact SHA-256 and identifies version 2.0.0 as unmerged and undeployed.

The v2 record model separates applications, programs, infrastructure, content releases, historical records, external systems, and concepts. Every version line has distinct release, Sites-save, commit, pull-request, deployment, data-schema, backup, verification, and rollback dimensions. Unknown values remain null; short Git prefixes remain explicitly partial and never become exact commit identities.

The derived Core projection contains only portfolio identity and version state. Raw legal, financial, health, customer, guest, staff, credential, communication, and application records remain in their sovereign Cells or external authoritative systems.
